# 焊机跳闸放行票据（Permit-to-Reset）

## 1. 要解决的问题

焊机过流跳闸后，原实现里任何人按下“告警复位”都会直接清除联锁
（`Line.clear_weld_alarm()` → `Welder.alarm_clear()`）：

- 不留申请人、不放行人；
- 不记录放行依据（凭哪张检修单、谁确认故障已排除）；
- 票据长期有效、可被无限次使用；
- 焊机维修/更换以后，旧票据仍然能放行。

本改动把复位改成**持票放行**：没有有效票据，联锁一律不释放（故障关闭 / fail-closed）。

## 2. 放行规则（全部满足才放行）

票据是一张有时效的数字票据（HMAC 签名令牌 + 服务端状态登记）。复位时
`PermitOffice.redeem_ticket()` 逐条校验：

1. **持票人是登记在案的操作人角色**（未知身份/非操作人拒绝）；
2. **签名有效**（票据由票据办公室签发，篡改即拒，记 `bad-signature`）；
3. **设备匹配**：票据上的设备必须是当前这台焊机；
4. **换代匹配**：票据签发时的设备“代次（generation）”必须等于当前代次；
5. **跳闸匹配**：票据必须对应当前这一次未关闭的跳闸（trip 序号）；
6. **持票操作人匹配**：票据上具名的操作人必须与按复位的人一致；
7. **未过期**：当前时间早于 `expires_at`（默认 120 分钟，签发时可在
   1～480 分钟内指定）；
8. **状态为 active**：已使用 / 已撤销 / 已换代失效 / 已过期的票据一律拒绝。

校验通过后，票据**一次性核销**（置 `used`、记录使用人和时间），同时关闭本次
跳闸记录，然后才清除焊机联锁。票据不可重放：再次使用会因为跳闸已关闭而被拒。

### 自动失效

- **过期**：到期点后首次使用/列表/签发时自动置 `expired`，或由到期扫描处理。
- **设备换代**：维修人员登记“焊机换代/改造”（`replace_welder`，必须给依据）后
  generation 加一；该设备所有 active 票据立即置 `superseded`，未关闭的跳闸关闭。
  旧票即使在有效期内也无法放行。

## 3. 角色与职责（故障关闭的最小身份目录）

| 角色 | 工号（首启种子，部署须替换） | 能做什么 |
|---|---|---|
| 主管 supervisor | `u-supervisor` | 签发票据、撤销票据 |
| 维修 maintenance | `u-maintenance` | 登记设备换代/改造（使旧票失效） |
| 操作人 operator | `u-operator` | 申请/持票复位（只能用具名给自己的票） |

> 真实部署应把种子身份替换为现场人员目录（工牌/AD 等），并保护好 HMAC 密钥
> （`permit.secret`，文件权限 600，建议迁移到 KMS/HSM；多方签发可改用非对称签名）。

## 4. 票据字段

票据号、设备、代次、跳闸序号、申请人、**放行依据（basis）**、有效期（分钟）、
签发人、签发时间、过期时间、具名操作人、状态、使用时间/使用人、撤销原因。

操作员拿到的“票据”是一段紧凑令牌：`<base64url(规范化JSON载荷)>.<HMAC-SHA256标签>`，
载荷含 `v/tid/eq/gen/trip/op/iat/exp`。服务端登记（`permit.ticket.*`）是状态的
唯一事实来源，签名保证票据不可伪造/篡改。

## 5. 审计与可追责

- `permit.journal`：**只追加**的 JSONL 台账，每行带 `seq/时间/动作/行为人/明细/prev/hash`，
  用 SHA-256 哈希链串联；改动或删除任意历史行会让链校验失败，此时票据办公室
  启动即拒（`journal-tampered`），拒绝一切放行。
- 记录的动作：`trip.opened`、`ticket.issued`、`ticket.released`、`release.denied`
  （**所有拒绝也记账**，含原因）、`ticket.revoked`、`ticket.expired`、
  `ticket.superseded`、`generation.bumped`、`trip.closed`。
- 每条票据动作同时发布 `permit` 事件到产线总线，进入既有事件流和审计查询页。

## 6. 接口

| 方法/路径 | 角色 | 说明 |
|---|---|---|
| `POST /api/weld/alarm` | — | 模拟过流跳闸；自动打开一条跳闸记录 |
| `POST /api/weld/permits/issue` | supervisor | 开票：`applicant/basis/issued_by/operator?/ttl_minutes?`，返回票据与令牌 |
| `POST /api/weld/clear` | operator | **凭票复位**：`ticket`（令牌）+ `operator`，返回谁、依据、哪张票放行 |
| `POST /api/weld/permits/revoke` | supervisor | 撤销票据（需原因） |
| `POST /api/weld/replace` | maintenance | 焊机换代/改造（需依据），旧票全部失效 |
| `GET  /api/weld/permits` | — | 票据清单（状态/申请人/操作人/过期时间/依据） |

控制台“操作 → 焊接与张力”面板已改为：签发、凭票复位、撤销、换代、票据清单。

## 7. 存储（原子快照目录 `data/snap/`）

- `permit.secret`：HMAC 密钥（首启随机生成）
- `permit.state`：身份目录与设备代次
- `permit.trip.<eq>.<n>`：跳闸记录；`permit.ticket.<id>`：票据登记
- `permit.journal`：哈希链只追加台账
- `weld.latch`：新增 `generation` 字段，重启后与票据办公室对齐

## 8. 与现场安全系统的关系（重要）

本实现是**管理层的“工作许可（permit-to-work）”软件闸门**，解决的是
“谁、凭什么、在多长时间内可以复位”的可追溯问题。它**不能替代**：

- 过流原因已排除的现场确认（挂牌上锁 LOTO、验电、绝缘检查等）；
- 安全继电器/安全 PLC 等**独立硬件安全联锁**；
- 适用功能安全标准（如产线对应的安全控制系统要求）的评估与认证。

真正的复位回路应由独立安全硬件执行，软件票据办公室作为其授权前置条件；
上线前需由安全工程师评估，并把身份目录、密钥管理、时钟同步（NTP）和
代次登记纳入现场管理规程。
